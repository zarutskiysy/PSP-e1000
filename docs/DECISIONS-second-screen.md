# Decisions: feat/second-screen

Builder log, overnight 2026-11-07. The owner was asleep, so every choice below was made without asking.

| # | Decision | Why |
|---|---|---|
| 1 | Codec is PSP-order RGB565 (`B<<11 \| G<<5 \| R`) in 16×16 tiles (30×17 = 510). Only tiles that differ from the previous *sent* frame are sent. | Scout recommendation (`docs/research/second-screen.md`). Lossless, so text stays sharp. Decoding is plain memcpy, and the PSP framebuffer is natively 565. |
| 2 | Tiles carry absolute pixels, not deltas. | A lost chunk only leaves some tiles stale, never a corrupted chain. The PSP sets `NEED_KEY` in its ACK and the Mac sends a keyframe. A keyframe is also forced every 5 s (`--key-interval`). |
| 3 | Solid tiles (all one colour) cost 4 bytes instead of 514. | Desktops are full of flat areas. On the synthetic desktop this makes the raw keyframe 242 KiB, and LZ4 brings it to 20 KiB. |
| 4 | LZ4 *block* per chunk, mode `auto` (used only if it saves ≥10 %). The PSP uses its own ~50-line safe decoder (`scr_lz4_decompress`), not pspdev's liblz4. | One portable C file compiles for the PSP, macOS tests and ctypes without link-flag issues. It is checked against python-lz4 output in `test_c_lz4_matches_reference` and fuzzed under ASan. If it proves slow on hardware, liblz4's `LZ4_decompress_safe` is a drop-in swap. |
| 5 | Chunk payload ≤ 64 KiB (16-byte chunk header + body ≤ 65520). The PSP parser buffer is 64 KiB + 64. | Keeps buffers small on both sides, as the brief asks. A full raw frame is 5 chunks. |
| 6 | Flow control: a window of N unacknowledged frames (default 2). The PSP ACKs after presenting the LAST chunk of a frame. An ACK for frame k also releases older frames. With no ACK for `--ack-timeout` s, the Mac drops the window and sends a keyframe. | Simple, and it keeps the pipe busy (bridge or USB) without unbounded queueing. Tested with a slow fake PSP (`test_flow_control_window`). |
| 7 | The PSP decodes into a RAM canvas. On present it copies only the dirty tiles to the 565 framebuffer at `0x44000000` (stride 512, uncached). The stats line is drawn over the bottom 8 rows, and those tiles are re-copied before each redraw. | The overlay must not corrupt the image that the dirty-tile diff assumes. |
| 8 | No vsync wait when presenting. | Waiting for vblank would cap fps and add up to 16 ms latency. Tearing is acceptable for a POC; adding `sceDisplayWaitVblankStart` later is one line. |
| 9 | The io is picked in one place (`open_io`): `screen.cfg` (one word) → emulator autodetect (mailbox) → menu (○ MACLINK, ✕ HOSTFS, △ mailbox, □ replay). | The brief asked for one switch point. The buttons match `examples/echo` so the morning steps don't conflict. |
| 10 | Extra io **replay**: the Mac can record the exact byte stream (`--transport record:FILE`). The EBOOT plays `stream.bin` from its folder in a loop at ~30 fps. | Gives a deterministic PPSSPP test of the real decoder at full speed with no bridge. It was pixel-exact before the mailbox io existed. |
| 11 | `make -C screen/psp` builds with USB by default (`USB ?= 1`, main's `usb.mk`). `USB=0` builds emulator-only. | One-command build gives the hardware build. It also runs in PPSSPP, where the mailbox is autodetected. |
| 12 | My own one-way throughput probe (`psp_screen.py probe`, types 0x50–0x53), in addition to main's round-trip `tools/usb_probe.py echo`. | The second screen only needs Mac→PSP throughput, with the PSP as a sink. It is measured at 16/64/256 KiB host transfer sizes, as the brief asked. Timing is reported from both sides: Mac wall clock and PSP µs between first and last probe frame. |
| 13 | Mac capture uses ScreenCaptureKit one-shot `SCScreenshotManager` (macOS 14+, region via `sourceRect`, GPU-scaled to 480×272), falling back to `mss`. No `SCStream` delegate yet. | It is the simplest supported API from pyobjc. Per-frame latency is **UNVERIFIED** (no permission tonight). If it limits fps, an `SCStream` delegate is the next step. CGVirtualDisplay (DeskPad-style) was not attempted; it is stretch scope. |
| 14 | Fake PSP (`tools/fake_psp_screen.py`) runs the PSP's C decoder through ctypes (`libscrcodec.dylib`, rebuilt automatically). A ctypes struct mirror is checked against `scr_dec_struct_size()`. A pure-Python reference decoder is also kept. | Tests exercise the exact PSP code. Two independent decoders catch encoder bugs that one decoder would mirror. |
| 15 | PPSSPP port 45672 (assigned by main). Emulator screenshots are taken only **after** the sender finishes. | Taking `ppsspp.py shot` mid-stream left the CPU stepping and froze the mailbox (reported to main). |
| 16 | CFW assumption: 6.60/6.61 + PRO-C / LME / ARK-4, the same as main's decision #1. | Exact CFW unknown. |
| 17 | HOSTFS mode: chunks ≤ 3000 B, `SCR_CHUNK_ACK` (0x42) stop-and-wait per chunk (link flag `PSP_LINK_F_ACK_REQ`), window 1. Automatic for `--transport hostfs`. | usbhostfs's Mac→PSP async buffer is 4 KiB and drops overflow (review round 1). Slow, but correct; MACLINK stays the real path. |
| 18 | `--lz4 on` falls back to raw for chunks LZ4 can't shrink. | Incompressible chunks grew past 64 KiB (65551 B), which overflows the 64 KiB mailbox ring (review round 1). |
| 19 | The sender reconnects after a `ConnectionError` (default 30 s): re-open, re-handshake, fresh encoder (so the next frame is a keyframe). | PSP restart or unplug mid-stream used to end in a traceback (review round 1). |
| 20 | Probe: PSP-timed MB/s excludes the first frame's bytes (its arrival starts the clock). | Review round 1; the probe is the app-level ceiling (USB + parse/CRC), not raw USB. |
